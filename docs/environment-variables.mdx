---
title: Environment Variables
description: Configuration used by local and self-hosted OneGlanse deployments.
---

Copy `.env.example` to `.env` in the repository root. `pnpm local`, `pnpm auth`, and `pnpm self-host` also create it when missing. Startup generates `BETTER_AUTH_SECRET` and `INTERNAL_CRON_SECRET` when they are blank or retain the template placeholder.

“Set by user” below means the standard setup needs you to provide a value. The scripts and Compose file set or override several other values. Keep secrets out of version control.

## Application and data services

| Variable | Set by user? | Standard value or behavior | Purpose |
|---|---|---|---|
| `APP_URL` | Self-host: yes | Local script uses `http://localhost:3000` | Public Web URL and authentication base URL |
| `API_BASE_URL` | Self-host: yes | Local script uses `http://localhost:3000` | Web/API URL used by scheduled runs |
| `ONEGLANSE_APP_MODE` | Manual self-host: yes | Template is `local`; `pnpm local` forces `local`; VPS setup script sets `self-host` | Controls auth, scheduling, and proxy behavior |
| `DATABASE_URL` | No | Local Postgres URL in `.env.example`; Compose uses container `db` | PostgreSQL connection |
| `CLICKHOUSE_URL` | No | Local `http://localhost:8123`; Compose uses `clickhouse` | ClickHouse connection |
| `REDIS_HOST` | No | Local `localhost`; Compose uses `redis` | Redis host |
| `REDIS_PORT` | No | `6379` | Redis port |
| `REDIS_PASSWORD` | No for default stack | `redis` in template | Redis password |
| `BETTER_AUTH_SECRET` | No for scripted setup | Generated from blank or placeholder | Web session signing secret |
| `INTERNAL_CRON_SECRET` | No for scripted setup | Generated from blank or placeholder | Scheduled-run request token |

For a self-hosted deployment, set `APP_URL` and `API_BASE_URL` to the public HTTPS app URL. Recurring schedules use `API_BASE_URL`.

## Response analysis

Provider collection uses browser sessions. These settings control the separate analysis step after capture.

| Variable | Set by user? | Default | Purpose |
|---|---|---|---|
| `ANALYSIS_LLM_PROVIDER` | Only for Anthropic | `openai` | Selects `openai` or `claude` analysis |
| `OPENAI_API_KEY` | For OpenAI analysis | None | OpenAI key, or key for an OpenAI-compatible gateway |
| `ANTHROPIC_API_KEY` | For Anthropic analysis | None | Anthropic key |
| `OPENAI_BASE_URL` | No | Official OpenAI endpoint | Optional OpenAI-compatible base URL |
| `ANALYSIS_OPENAI_MODEL` | No | `gpt-4.1` | Model identifier sent to the OpenAI-compatible endpoint |
| `ANALYSIS_OPENAI_API` | No | `responses` | `responses` or `chat` transport; use `chat` for gateways that require Chat Completions |

The selected provider needs its corresponding key. For example, with an OpenAI-compatible gateway, set `OPENAI_API_KEY`, `OPENAI_BASE_URL`, and the model and transport that gateway supports.

## Web sign-in

| Variable | Set by user? | Default | Purpose |
|---|---|---|---|
| `GOOGLE_CLIENT_ID` | Only for Google sign-in | None | Google OAuth client ID for the OneGlanse web app |
| `GOOGLE_CLIENT_SECRET` | Only for Google sign-in | None | Google OAuth client secret for the OneGlanse web app |

These values do not authenticate the Gemini or Google AI Overview browser collectors.

## Provider-session transfer

| Variable | Set by user? | Default | Purpose |
|---|---|---|---|
| `AGENT_AUTH_UPLOAD_TOKEN` | Yes for VPS upload | None | Bearer token shared by desktop upload and Agent |
| `AGENT_AUTH_UPLOAD_URL` | For a custom or HTTPS endpoint | None | Full session-upload URL, including `/auth/sessions` |
| `ONEGLANSE_VPS_IP` | For the IP shortcut | None | Derives `http://<IP>:3333/auth/sessions` for `pnpm auth` and `pnpm upload:vps` |
| `AGENT_AUTH_ROOT_DIR` | No | Local storage or Compose `/storage/auth` | Override for local session storage |

Set either `AGENT_AUTH_UPLOAD_URL` or `ONEGLANSE_VPS_IP` on the desktop, plus the token. An explicit upload URL takes precedence. The IP shortcut uses plain HTTP; see [Self-Hosted Setup](/self-hosted-setup#session-upload-security) for safer network paths.

## Self-host proxy

Self-host browser runs require ThorData proxy discovery in the current implementation. Local runs do not use this proxy path.

| Variable | Set by user? | Default | Purpose |
|---|---|---|---|
| `THORDATA_PROXY_API_URL` | Yes for self-host | None | ThorData API link that returns proxy host and port entries |
| `PROXY_SCHEME` | No | `http` | `http` or `https` scheme for returned proxy endpoints |

Use a ThorData API link that returns usable proxies and authorizes your VPS. A sticky session can help keep a prompt run on one residential IP. The Agent does not currently accept an arbitrary proxy URL in place of the ThorData discovery API.

## Agent and browser runtime

| Variable | Set by user? | Standard value or behavior | Purpose |
|---|---|---|---|
| `DEBUG_ENABLED` | No | `false` | Enables verbose Agent logging |
| `CAMOUFOX_HEADLESS_MODE` | No | Browser runtime selects a mode; local script overrides it | Browser display mode: `virtual`, `headful`, or `headless` |
| `CAMOUFOX_PYTHON_BIN` | No | Auto-selected | Override Python binary for the local browser runtime |
| `CAMOUFOX_PIP_SPEC` | No | Local script uses `cloverlabs-camoufox==0.5.5`; Docker build uses its own default | Browser Python package spec |
| `CAMOUFOX_BROWSER_CHANNEL` | No | Local script uses `official/stable/135.0.1-beta.24`; Docker build uses its own default | Browser binary channel |

The last two values affect browser preparation or image builds. A published Agent image already contains its browser runtime.

## Database containers

These values configure the standard Docker Compose containers. The defaults are present in `.env.example` and in Compose.

| Variable | Set by user? | Default | Purpose |
|---|---|---|---|
| `POSTGRES_USER` | No | `postgres` | Postgres user |
| `POSTGRES_PASSWORD` | No | `postgres` | Postgres password |
| `POSTGRES_DB` | No | `oneglanse` | Postgres database |
| `CLICKHOUSE_DB` | No | `oneglanse` | ClickHouse database |
| `CLICKHOUSE_USER` | No | `default` | ClickHouse user |
| `CLICKHOUSE_PASSWORD` | No | `clickhouse` | ClickHouse password |

For a public deployment, replace template database passwords with strong values before the first start. Keep related connection values consistent when you change them.
