title: Self-Hosted Setup
description: Deploy the always-on OneGlanse app on an Ubuntu VPS.
---

Self-host mode runs Web, Agent, Postgres, ClickHouse, and Redis through Docker. It supports manual prompt runs and recurring schedules. Provider sign-in happens on a desktop machine; you then upload the sessions to the Agent on the VPS.

## Requirements

- An Ubuntu 22.04 or 24.04 VPS and a domain whose DNS A record points to it
- A non-root user with `sudo` access
- An OpenAI or Anthropic API key, or an OpenAI-compatible endpoint and its API key
- Provider accounts and a desktop machine for browser sign-in
- A ThorData residential proxy API endpoint for browser traffic from the VPS

Datacenter IPs are often challenged by provider interfaces. The current self-host browser path uses ThorData proxy discovery and requires `THORDATA_PROXY_API_URL`. See [Environment Variables](/environment-variables) for that setting.

## Recommended automated setup

On the VPS, connect as a non-root sudo user. The script rejects root. Set the DNS A record before starting so certificate issuance can succeed.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/oneglanse/oneglanse/main/scripts/setup-vps.sh)
```

The interactive script asks for a domain, install directory, analysis key, proxy API URL, and upload token. It installs missing Docker, Node.js, Git, and nginx dependencies, configures `.env`, starts the Docker stack, configures nginx and attempts a Let's Encrypt certificate, and opens firewall ports if `ufw` is installed. It generates an upload token when you leave that prompt blank. It also handles first-run Docker group access for its setup session.

The script opens port 3333 for session upload and can continue if certificate issuance fails. Review the [session-upload security options](#session-upload-security) and confirm HTTPS works before using the public app. Run it with `bash <(...)` so its prompts can read your terminal.

You can also clone the repository and run the script from that checkout:

```bash
git clone https://github.com/oneglanse/oneglanse.git /tmp/oneglanse
bash /tmp/oneglanse/scripts/setup-vps.sh
```

After either setup path, continue at [Capture and upload provider sessions](#capture-and-upload-provider-sessions).

## Manual setup

### 1. Prepare the VPS and DNS

Use a non-root sudo user. Point your app hostname, such as `app.example.com`, to the VPS IP before requesting a certificate.

Install Docker, Node.js 20 or newer, Git, nginx, and Certbot. For example, on Ubuntu:

```bash
sudo apt-get update
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker "$USER"
newgrp docker
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs git nginx certbot python3-certbot-nginx
```

### 2. Clone and configure

```bash
git clone https://github.com/oneglanse/oneglanse.git "$HOME/oneglanse"
cd "$HOME/oneglanse"
cp .env.example .env
```

Edit `.env`. Set your public URL, one analysis model, the ThorData API endpoint, and an upload token:

```dotenv
APP_URL=https://app.example.com
API_BASE_URL=https://app.example.com
ONEGLANSE_APP_MODE=self-host
OPENAI_API_KEY=your-key
THORDATA_PROXY_API_URL=https://your-thordata-api-link
AGENT_AUTH_UPLOAD_TOKEN=your-long-random-secret
```

For Anthropic, set `ANTHROPIC_API_KEY` and `ANALYSIS_LLM_PROVIDER=claude` instead of `OPENAI_API_KEY`. Keep `ONEGLANSE_APP_MODE=self-host`: the automated setup script sets it, but manual setup must set it in `.env`. The bootstrap command generates `BETTER_AUTH_SECRET` and `INTERNAL_CRON_SECRET` if they are blank or still placeholders. See [Environment Variables](/environment-variables) for all supported values.

### 3. Start the stack

```bash
node scripts/run-compose.mjs bootstrap
```

This uses published application images when available. If Docker reports no compatible image manifest, it falls back to a local build. The Web app listens on `127.0.0.1:3000`; Postgres, ClickHouse, and Redis also bind to loopback. The Agent upload API listens on port `3333`.

Check the containers:

```bash
docker ps
```

Look for `oneglanse-web`, `oneglanse-agent-worker`, `postgres_db`, `clickhouse_db`, and `redis`.

### 4. Configure nginx and HTTPS

Create `/etc/nginx/sites-available/oneglanse` with your real hostname:

```nginx
server {
    listen 80;
    server_name app.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/oneglanse /etc/nginx/sites-enabled/oneglanse
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d app.example.com
```

Verify `https://app.example.com` loads before creating an account.

## Capture and upload provider sessions

On your desktop machine, clone the repository and install dependencies if you have not already. Configure an upload target in that checkout's `.env`, using the same token as the VPS. The default IP shortcut constructs a plain HTTP URL on port 3333:

```dotenv
ONEGLANSE_VPS_IP=YOUR_VPS_IP
AGENT_AUTH_UPLOAD_TOKEN=your-long-random-secret
```

Run `pnpm auth` to prepare the Camoufox browser, build the required workspace packages, and open the local provider sign-in UI on port 3100. The full local app stack and its database services are not required.

```bash
pnpm auth
```

Finish sign-in in the browser, return to the terminal, and press Enter. If sessions changed and upload is configured, the command asks whether to upload them. To send existing sessions later without signing in again:

```bash
pnpm upload:vps
```

For an HTTPS upload endpoint, set `AGENT_AUTH_UPLOAD_URL` to its full `/auth/sessions` URL instead of using `ONEGLANSE_VPS_IP`. You must provide TLS termination or a secure tunnel for that endpoint. The Agent does not provide HTTPS itself.

Open the Providers page on the VPS app to check connection status. Then add prompts and run them. Configure recurring runs on the Schedule page.

## Updating

From the VPS checkout:

```bash
cd "$HOME/oneglanse"
git pull
node scripts/run-compose.mjs bootstrap
```

Bootstrap pulls current configured images and recreates containers. Expect a brief interruption during recreation. If you changed `.env`, this command also applies the new values.

## Session-upload security

The Agent exposes `POST /auth/sessions` on port 3333 and requires `AGENT_AUTH_UPLOAD_TOKEN`. The IP shortcut sends the token and provider sessions over plain HTTP. Use a private network, VPN, or an HTTPS reverse proxy for uploads. Restrict port 3333 to your source IP when possible. The automated script opens that port broadly, so narrow the firewall rule after setup if you use a public VPS.

For example, with `ufw` and a stable desktop public IP:

```bash
sudo ufw delete allow 3333/tcp
sudo ufw allow from YOUR_DESKTOP_PUBLIC_IP to any port 3333 proto tcp
```

Do not expose the database ports. In the Compose file, they bind to loopback. See the repository [security policy](https://github.com/oneglanse/oneglanse/blob/main/SECURITY.md) for the full data-flow boundary.

For deployment problems, see [Troubleshooting](/troubleshooting).
