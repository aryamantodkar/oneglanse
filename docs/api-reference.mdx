## Commands

| Command | Behavior |
|---|---|
| `pnpm local` | Prepare dependencies and browser files, start local data services, run migrations, then start Web and Agent from source. |
| `pnpm auth` | Open the local provider sign-in UI. If sessions changed and an upload target is configured, prompt to upload them. |
| `pnpm upload:vps` | Upload existing local sessions without reopening sign-in. Requires an upload target and token. |
| `pnpm self-host` | Pull and start configured Docker images. Build locally only when Docker reports no compatible image manifest. |
| `pnpm self-host:build` | Build application images from source and start the self-hosted stack. |

## Application modes

| Capability | Local | Self-host |
|---|---|---|
| Interactive provider sign-in | Yes | Capture locally and upload |
| Manual prompt runs | Yes | Yes |
| Recurring schedules | No | Yes |
| Provider browser proxy | Not used by mode | ThorData discovery required |

`pnpm local` forces local mode. The VPS setup script sets self-host mode. For manual VPS setup, set `ONEGLANSE_APP_MODE=self-host` in `.env` before `pnpm self-host` or its Node script equivalent. See [Environment Variables](/environment-variables).

## Important routes

| Route | Purpose |
|---|---|
| `/dashboard` | Visibility metrics |
| `/prompts` | Manage prompts |
| `/sources` | Inspect sources and citations |
| `/providers` | Manage provider connections |
| `/schedule` | Run prompts and, in self-host mode, configure a recurring schedule |
| `/people` | Manage team members in self-host mode |

The Agent also exposes `GET /health` and bearer-protected `POST /auth/sessions` on port 3333 for self-host session transfer.

## Session storage

Each auth group has a portable session bundle. Provider runtime profiles are stored separately and are seeded from the bundle when needed. The local capture flow can upload bundles to the self-hosted Agent. See [Self-Hosted Setup](/self-hosted-setup#capture-and-upload-provider-sessions) for the operational steps.
